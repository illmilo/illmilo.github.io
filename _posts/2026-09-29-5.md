### Признаки кратности

Для решения задания потребуется сразу 2 признака кратности: кратность основанию числа $b$ или кратность $b+1$.

#### Кратность $b$

> Число, записанное в $b$-ричной системе счисления, делится на $b$ тогда и только тогда, когда его **последняя цифра -- это ноль**.
{: .prompt-info }

Пусть $a\_i$ -- это цифра в разряде с индексом $i$.

Тогда если мы переведем $b$-ричное число, состоящее из таких цифр, получим:

$$
(a_n ... a_1 a_0)_b = a_n \cdot b^n + ... + a_1 \cdot b^1 + a_0 \cdot b ^ 0
$$

Вынесем общий множитель $b$ за скобки, получим:

$$
a_0 + b\cdot (a_1 + ... + a_n \cdot b^{n-1})
$$

Следовательно, кратность числу $b$ всего выражения зависит от значения $a\_0$. Учитывая, что $0 \leq a\_0 \leq b - 1$, единственное значение, которое даст кратную $b$ сумму, это $a\_0 = 0$.

#### Кратность $b+1$

> Число, записанное в $b$-ричной системе счисления, делится на $b+1$ тогда и только тогда, когда **разность** суммы **разрядов с четными индексами** и суммы **разрядов с нечетными индексами** делится на $b+1$.
>
> Другими словами, если **знакочередующаяся сумма всех цифр** кратна $b+1$.
{: .prompt-info}

*(Аналог признака делимости на 11 в десятичной системе).*

Рассмотрим остатки от деления степеней основания $b$ на $(b+1)$:

Остаток|Пояснение
-|-
$b^0 = 1 \equiv 1 \pmod{b+1}$|При делении $b^0 = 1$ на $b+1$ получаем остаток $1$
$b^1 = b = (b+1) - 1 \equiv -1 \pmod{b+1}$|При делении $b^1=b=(b+1)-1$ на $b+1$ получаем остаток $-1$
$b^2 = ((b+1)-1)^2 = (b+1)^2 - 2(b+1) + 1 \equiv 1 \pmod{b+1}$|По формуле $(a-b)^2=a^2-2ab+b^2$ получаем $b^2=((b+1)-1)^2=(b+1)^2 - 2(b+1) + 1$. Здесь все слагаемые кратны $b+1$, кроме последнего (и он же остаток) $+1$.

И так далее: **четные** степени $b^{2n}$ при делении на $b-1$ дают остаток $1$, нечетные $b^{2n+1}$ -- остаток $(-1)$. Вы можете расписать $b^3$ и $b^4$, чтобы проверить повторяемость.

Пусть число в $b$-ричной записи принимает цифры $a\_i$, где $i$ -- индекс разряда. Тогда при переводе в десятичную систему получим:

$$
a_n\cdot b^n + a_{n-1}\cdot b^{n-1} + \dots + a_1\cdot b^1 + a_0 \cdot b^0
$$

> **Вычет по модулю** -- это **остаток от деления** одного целого числа на другое число, которое называется модулем.
{: .prompt-info }

Заменим каждый множитель $b^i$ на его вычет по модулю $(b+1)$:

$$a_0 - a_1 + a_2 - a_3 + \dots + (-1)^n a_n \equiv 0 \pmod{b+1}$$

Или:

$$
(a_0 + a_2 + a_4 + ...) - (a_1 + a_3 + a_5 + ...) \equiv 0 \pmod{b+1}
$$

Получается, что делимость $b$-ричного числа на $b+1$ зависит от делимости **знакопеременной суммы** его цифр на $b+1$.

## Поиск $N$

Один из распространенных типов заданий -- это поиск $N$. В этом задании нужно ориентироваться на разрядность опорного числа.

### Суть задания

> *Апробация 04.03.26*
>
> На вход алгоритма подаётся натуральное число $N$. Алгоритм строит по нему новое число $R$ следующим образом.
>
> 1. Строится двоичная запись числа $N$.
> 2. Далее эта запись обрабатывается по следующему правилу:
>
>    a) если число $N$ делится на $3$, то к этой записи дописываются три последние двоичные цифры;
>   
>    б) если число $N$ на $3$ не делится, то остаток от деления умножается на $3$, переводится в двоичную запись и дописывается в конец числа.
>
>    Полученная таким образом запись является двоичной записью искомого числа $R$.
>
> 3. Результат переводится в десятичную систему и выводится на экран.
>
> Например, для исходного числа $6\_{10} = 110\_2$ результатом является число $110110\_2 = 54\_{10}$, а для исходного числа $4\_{10} = 100\_2$ это число $10011\_2 = 19\_{10}$.
>
> Укажите максимальное число $N$, после обработки которого с помощью этого алгоритма получается число $R$, ближайшее к $130$.

### Опорное число

Наша первая задача -- перевести опорное число $R = 130$ в двоичную систему счисления. Сделать это можно вручную или с помощью встроенного в ОС калькулятора в режиме "Программист".

$$130_{10}=10000010_{2}$$

Разрядность -- 8 цифр.

**Обратите внимание**: число $130$ очень близко к степени $2^7=128$. Это значит, что совсем рядом 7-значные числа.

Следовательно, мы получаем 2 опорных числа с **разным количеством цифр**: 

$$
R_1 \approx 130_{10} \approx 10000010_{2}\\
R_2 \approx 127_{10} \approx 1111111_2
$$

> Обращайте внимание на близость опорного числа к **степени основания**. Если опорное число близко к какой-либо **степени основания**, это значит, что вы находитесь близко к числам с **другой разрядностью**: то есть, с другим *количеством цифр*. Подробнее смотрите в [посте о системах счисления]({% post_url 2026-09-02-intro %}#перевод-из-10-ной).
{: .prompt-warning }

### Пункт а)

Согласно кратности чисел с основанием $b = 2$ числу $b + 1 = 3$, двоичное число $N$ делится на $3$, если сумма цифр четных разрядов минус сумма цифр нечетных разрядов кратна $3$.

Причем обратим внимание, что к исходному числу $N$ дописывались 3 цифры справа. Следовательно, число $N$ будет иметь на $3$ цифры меньше, чем у опорного числа.

> Важно определять, сколько цифр дописывалось к $N$ для получения $R$, чтобы понять разрядность $N$.
{: .prompt-warning }

* Для $R\approx 10000010\_2$ получается $N\approx 10000\_{2}$. Здесь сумма четных минус сумма нечетных разрядов дает $1$, нам же нужно получить $0$, поскольку $0 \equiv 0 \pmod{3}. Значит, нужно вместо какого-то нуля на нечетном разряде поставить $1$.

    Если поставить $1$ в разряде $3$, то число сильно увеличится и уйдет далеко от опорного. Значит, стараемся минимизировать изменения и поставить цифру справа; то есть, в разряде $1$.

    Получаем $N=10010\_{2}$. Дописав $3$ последние цифры получим число $R=10010010\_2 = 146\_{10}$.
* Для $R\approx 1111111\_2$ получается $N\approx 1111\_2$. Здесь сумма четных минус сумма нечетных дает $0$ -- подходит! Прибавив 3 последние двоичные цифры, получим $R=1111111\_2=127\_{10}$.

### Пункт б)

Переведем все возможные остатки от деления на $3$, кроме $0$ -- это $1$ и $2$. Переведем эти остатки, умноженные на $3$, в десятичную систему счисления.

$$
1\cdot 3 = 3_{10} = 11_2\\
2\cdot 3 = 6_{10} = 110_2
$$

Остаток $1$ получится при разности суммы четных разрядов и нечетных разрядов равной $-2$ или $1$.

Остаток $2$ -- при разности равной $-1$ или $2$.

Можете вычислить остатки от деления отрицательных чисел на $3$ самостоятельно исходя из логики, что все возможные остатки от деления на $3$ -- это $0, 1, 2$, других остатков быть не может по математической аксиоме формирования остатков от деления.

**Остаток $1$**:

* $R\approx 10000010\_2$: $N\approx 100000\_2$. Разность четных и нечетных $-1$. Ближе всего получить разность $-2$, а не $1$. Для этого в разряд $1$ можем поставить $1$. Итого получим $N=100010\_2$, для которой $R=10001011\_2=139\_{10}$.
* $R\approx 1111111\_2$: $N\approx 11111\_2$. Разность четных и нечетных $1$: значит, $N = 11111\_2$ подходит. Для него $R=1111111\_2 = 127\_{10}$.

**Остаток $2$**:

* $R\approx 10000010\_2$: $N\approx 10000\_2$. Разность $= 1$, ближе будет $=2$, значит, $N = 10001\_2$ подходит. Тогда $R=10001110\_2=142\_{10}$.
* $R\approx 1111111\_2$: $N\approx 1111\_2$. Разность $=0$. Этот вариант вообще можно не рассматривать, тут нужно менять как минимум две четные либо две нечетные цифры, а это отбросит от изначального числа очень далеко.

### Выбор числа

Итак, из всех претендетов самым близким оказалось число $R=127$, при котором в пункте а) $N=1111\_2=15$, в б) $N=11111_\2=31\_{10}$. Нам нужно взять максимальное число -- это $31$. Это верный ответ к заданию.

### Программный способ решения

При программной способе решения рекомендуется как минимум научиться самостоятельно определять две функции: функцию перевода и функцию остатка от деления. При этом обратите внимание, что некоторые авторские задания включают в себя более сложные действия, такие как замена всех цифр. На экзамене такие задания встречаются редко.

В любом случае, я рекомендую научиться решать это задание вручную, так как составители рассчитывают на ручное решение этого задания. Программный способ может вызвать трудности при появлении сложных манипуляций над исходным числом $N$, поэтому не является на 100% надежным.

Определим функцию `per(n, b)`, которая переведет десятичное число $n$ в $b$-ричную систему счисления:

```python
def per(n, b):
    s = ''
    while n:
        s = str(n % b) + s
        n //= b
    return s
```

Объяснение алгоритма можно найти в [посте о системах счисления]({% post_url 2026-09-02-intro %}#перевод-из-10-ной).

Для реализации **подачи натурального числа $N$** используем технику **брутфорса** -- подстановки всех возможных вариантов. Диапазон берем из головы. Как правило, ответ в заданиях ограничивается значениями до $10 000$, поэтому берем такой диапазон для $N$:

```python
for n in range(10_000, 1, -1):  # максимальный n => от большего к меньшему
```

Реализуем шаг 1 -- построим двоичную запись числа с использованием функции `per(n, b)`:

```python
    r = per(n, 2)   # сохраним в r двоичную запись n -- результат перевода
```

Реализуем шаг 2 пункт а: если число $N$ делится на 3, то к записи $R$ нужно прибавить три последние двоичные цифры:

```python
    if n % 3 == 0:  # если n делится на 3
        r = r + r[-3:]  # прибавить к предыдущему r срез от -3 индекса (последние 3 цифры)
```

Реализуем шаг 2 пункт б: если число $N$ не делится на 3, то к записи $R$ в конец приписать остаток от деления $N$ на 3, умноженный на 3 и записанный в двоичной системе счисления:

```python
    else:
        r = r + per(n % 3 * 3, 2)   # прибавить к r переведенный в двоичную систему остаток от деления n на 3, умноженный на 3
```

Реализуем шаг 3: переведем число $R$ в десятичную систему счисления, используя функцию `int(строчное_число_с_основанием_base, base)`:

```python
    r = int(r, 2)   # переведем r из двоичной системы в десятичную
```

Осталось прописать условие **опорного числа**. Мы возьмем число $130$ с погрешностью:

```python
    if 130 - 5 <= r <= 130 + 5: # тычем в небо, берем погрешность +-5. если ничего не выведет, возьмем разброс побольше
        print(n)
        break   # при поиске n можно брейкнуться, но следите за диапазоном: если нужен максимальный n, то от большего к меньшему, если же минимальный -- от меньшего к большему
```

**Итоговый шаблон программы**:

```python
def per(n, b):
    s = ''
    while n:
        s = str(n % b) + s
        n //= b
    return s

# при необходимости добавьте функцию суммы цифр
def sc(r):
    k = 0
    for c in r:
        k += int(c)
    return k

for n in range(_, _, _):  # укажите диапазон от большего к меньшему или наоборот
    r = per(n, _)    # укажите систему счисления
    if _:   # пропишите условие пункта а)
        r = _ + r + _   # пропишите изменения r по а)
    else:   # пункт б)
        r = _ + r + _   # пропишите изменения r по б)
    r = int(r, _)   # укажите систему счисления r
    if _:   # пропишите условие опорного числа
        print(n)
        break
```

## Поиск $R$

Вообще, прототип на нахождение $R$ встречается реже, чем прототип на поиск $N$. С точки зрения программного решения он выглядит чуть-чуть иначе, а вот с точки зрения ручного решения -- абсолютно также.

Ручное решение -- золотой стандарт, которым я рекомендую решать задание №5. Да, это сперва непросто, но вы будете защищены от провала на экзамене при непредвиденном прототипе такого задания.

При поиске $R$ важно также руководствоваться значением $N$. Единственное, в ответе не нужно будет вычленять $N$ из подходящего $R$, хотя скорее всего значение $N$ и так будет вам известно.

> Не забывайте, что $N$ **не имеет незначащих нулей**. Это частая ошибка новичков.
{: .prompt-danger }

### Суть задания

> *Демоверсия 2027*
>
> На вход алгоритма подаётся натуральное число $N$. Алгоритм строит по нему новое число $R$ следующим образом.
>
> 1. Строится двоичная запись числа $N$.
> 2. Далее эта запись обрабатывается по следующему правилу:
>
>    а) если число N чётное, то к этой записи справа и слева дописываются по две единицы;
>
>    б) если число N нечётное, то в конец двоичной записи (справа) дописываются два нуля, а в начало (слева) дописывается единица.
>
>    Полученная таким образом запись (в ней на три или четыре разряда больше, чем в записи исходного числа N) является двоичной записью искомого числа R.
> 3. Результат переводится в десятичную систему и выводится на экран.
>
> Например, для исходного числа $13\_{10} = 1101\_2$ результатом является число $1110100\_2 = 116\_{10}$, а для исходного числа $6\_{10} = 110\_2$ это число $1111011\_2 = 123\_{10}$.
>
> Укажите наименьшее число $R$, превышающее $95$, которое может быть результатом работы данного алгоритма. В ответе запишите это число в десятичной системе счисления.

### Опорное число

Итак, $2^6\leq R\leq 2^7$, причем оно не близко к переходу разрядов. Следовательно, пользуемся лишь одним опорным числом:

$$
R=95_{10}=1011111_2
$$

### Пункт а)

Число с основанием системы счисления $b=2$ делится на $b$ тогда и только тогда, когда оканчивается на $0$.

$$
N=1...0_2\\
R=11N11_2
$$

Поскольку нам нужно наимеьшее число $R$, стараемся поставить максимальное количество $0$. Поскольку всего в опорном $R$ 7 цифр, а в шаблоне мы знаем уже 4, остается 3 цифры для $N$. Первую и последнюю цифру $N$ мы уже знаем. Осталось поставить один $0$ посередине. Получаем число:

$$
R=1110011_2=115_{10}
$$

### Пункт б)

$$
N=1...1_2\\
R=1N00_2
$$

В $R$ 7 цифр, 3 из них известны. Значит, $N$ состоит из 4 цифр. Причем первая и последняя известны. Для минимального значения $R$ ставим в оставшиеся две позиции нули.

$$
R=1100100_2=100
$$

### Выбор значения

Очень хороший знак -- это когда мы выбираем оптимальное число из а) и б). Это число $100$.

### Программное решение

Здесь от [программного решения на поиск $N$](#программное-решение) отличие одно -- числа $R$ в зависимости от выполнения пункта а) или б) **нелинейно увеличивают свое значение**, из-за чего будет некорректно первое выведеннео значение $R$ принимать за наименьшее или наибольшее.

> Из-за нелинейности роста $R$ нельзя вывести первое попавшееся значение и зачесть его в ответ. Оно может быть не наименьшим или наибольшим.
{: .prompt-danger }

Поэтому для верного ответа выгоднее всего использовать **списки**.

Определим функцию перевода и создадим пустой список:

```python
def per(n, b):
    s = ''
    while n:
        s = str(n % b) + s
        n //= b
    return s

a = []  # список
```

Брутфорсим $N$ и выполняем шаг 1:

```python
for n in range(1, 10_000):
    r = per(n, 2)   # строим двоичный n
```

Шаг 2 пункты а) и б):

```python
    if n % 2 == 0:
        r = '11' + r + '11'
    else:
        r = '1' + r + '00'
```

Шаг 3:

```python
    r = int(r, 2)
```

Условие опорного числа:

```python
    if r > 95:
        a.append(r) # сохраняем число в список, не выводим сразу
```

Поскольку все значения $R$, большие 95, сохранены в список, нам достаточно вывести наименьшее значение из списка, используя `min(a)` для **наименьшего** значения или `max(a)` для **наибольшего** значения:

```python
print(min(a))
```

```python
def per(n, b):
    s = ''
    while n:
        s = str(n % b) + s
        n //= b
    return s

def sc(r):
    k = 0
    for c in r:
        k += int(c)
    return k

a = []

for n in range(1, 10_000):
    r = per(n, _)   # указать систему счисления
    if _:           # условие пункта а)
        r = _ + r + _   # изменить r по а)
    else:           # пункт б)
        r = _ + r + _   # изменить r по б)
    r = int(r, _)   # указать систему счисления
    if _:   # указать условие опорного числа
        a.append(r)

print(min/max(a))   # оставить min для наименьшего или max для наибольшего
```
