Задание №17 проверяет умение **составить алгоритм** обработки числовой последовательности, записанной в текстовом файле, и **реализовать его** на языке программирования.

Задание|Время выполнения
-|-
№17|$\approx 10$ минут

---

## Суть задания

Вам дается файл, который нужно считать. По условию, данному в задании, нужно обработать **ПАРЫ** или **ТРОЙКИ** чисел -- это **идущие подряд элементы последовательности**.

> _Демоверсия 2027_
>
> В файле содержится последовательность натуральных чисел. Её элементы могут принимать целые значения от 1 до 100 000 включительно. Определите количество пар последовательности, в которых **остаток от деления на 33 хотя бы одного** из элементов равен **минимальному элементу** последовательности. В ответе запишите **количество** найденных пар, затем **максимальную из сумм элементов** таких пар. 
>
> В данной задаче под парой подразумевается _два идущих подряд_ элемента последовательности.

---

## Считывание файла

Вместе с заданием вам выдается файл `17.txt`, где на каждой строчке записано одно целое число. Наши задачи:

1. Поместить файл вашего решения `17.py` и `17.txt` **в одну директорию**;
2. Прочитать файл в программе
3. Перенести все числа из файла в список 

> Ниже приводятся два способа **считать числа** из файла. Они **одинаково эффективны**. Выбирайте тот, что пришелся вам по душе.
{: .prompt-info }

### Способ 1: Генератор списка
```python
f = [int(line) for line in open("17.txt")]
```
Этот способ читается так: *Возьми целое число (`int`) из каждой строки (`line`) для каждой строки в открытом файле (`open`)*.

### Способ 2: Функция `map()`

```python
f = list(map(int, open("17.txt")))
```

|Команда|Пояснение|
|-|-|
|**`open(...)`**|**Открывает** файл и читает его **построчно**.<br>Каждая строка считывается в **строчном типе данных**.<br>Возвращает **итеративный объект** `<_io.TextIOWrapper>`, который можно **перебрать** через `for`.|
|**`map(int, ...)`**|Встроенный инструмент-**трансформатор**.<br>Берет указанную функцию `int` и применяет её к **итеративному объекту**.|
|**`list(...)`**|**Преобразует** подготовленный поток от данных `map` в **список**.|

## Стратегия решения

Задание №17 делится на два этапа: поиск специального числа и непосредственно подбор пар/троек.

### Этап 1: Поиск специального числа

> Пример **специального числа** в условии задания: 
>
> *Найдите количество пар, в которых... а сумма элементов меньше, чем **максимальный элемент последовательности, оканчивающийся на 13***.
{: .prompt-info }

Мы не можем проверять пары, пока не узнаем это число. Поэтому программа всегда делится на **два независимых прохода**:

1. Сначала мы ищем это **специальное число** по всему списку.
2. Затем запускаем основной цикл для проверки пар/троек.

Обычно такое число можно записать в одну строку при помощи **генератора списка** и функций **`min()`** или **`max()`**.

```python
# Ищем максимальное число, которое делится на 11
spec = max([x for x in f if x % 11 == 0])
```

Конкретно для нашего задания поиск очень-очень прост:

```python
spec = min(f)
```

### Этап 2: Поиск пар/троек

Когда нас просят проверить элементы, стоящие рядом, мы начинаем перебирать наш список по **индексам** (назовем их `i`), чтобы суметь взять **соседние элементы**:

```python
# Для ПАР:
for i in range(len(f) - 1):
    a = f[i]      # Текущий элемент
    b = f[i + 1]  # Следующий за ним

# Для ТРОЕК:
for i in range(len(f) - 2):
    a = f[i]      # Первый
    b = f[i + 1]  # Второй
    c = f[i + 2]  # Третий
```

**Зачем `- 1` или `- 2` в `range()`?**
Представьте, что в списке 100 элементов (индексы от 0 до 99). 
Если мы ищем **пары** и дойдем до последнего индекса `i = 99`, то программа попытается взять `f[i + 1]`, то есть `f[100]`. Но сотого элемента не существует! Программа аварийно завершится с ошибкой `IndexError: list index out of range`. 

> Чтобы не получить **ошибку `IndexError`**, в `range` **вычитаем из длины** столько, сколько **максимально шагов вперед** мы делаем внутри цикла (для пар `-1`, для троек `-2`).
{: .prompt-danger }

#### Вспомогательные функции

Чтобы код в основном цикле не превращался в нечитаемую кашу из **гигантских логических выражений** в `if`, описывайте логические проверки в виде **отдельных маленьких функций**. Они должны возвращать **логические значения**, так что результат работы таких функций можно использовать в `if`, причем **сохранив отличную читаемость кода**.

> В файлах задания №17 очень часто встречаются **отрицательные числа**. В Python операция взятия остатка от деления для отрицательных чисел работает не так, как в математике. Например, `-15 % 10` вернет `5`, а `-13 % 10` вернет `7`. 
>
> Чтобы корректно проверять последнюю цифру числа или его значность, **всегда используйте функцию `abs()`**, которая позволит взять модуль числа, которая временно убирает знак минус.
{: .prompt-danger }

Пример красивых и безопасных функций:
```python
# Вернет True, если число трехзначное, иначе False
# Дословно название функции: цифры 3
def c3(n):
    return 100 <= abs(n) <= 999

# Вернет True, если число оканчивается на 3, иначе False
# Дословно название функции: кончается 3
def end3(n):
    return abs(n) % 10 == 3
```

Теперь в основном цикле условия будут читаться легко:
```python
    if 100 <= abs(a) <= 999 and abs(a) % 10 == 3: ... # БЫЛО
    if c3(a) and end3(a): ... # СТАЛО
```

> Если количество элементов пары/тройки, которые должны подходить по критерию, конкретное, например:
>
> _Ровно два трехзначных элемента в тройке_
>
> То можно складывать логические значения `True` (`1`) и `False` (`0`), чтобы понять, для скольки элементов всего функция вернула `1` (то есть элемент подошел под критерий):
>
> **`if c3(a) + c3(b) + c3(c) == 2: ...`**
{: .prompt-tip }

### Вывод ответа

Обычно в задаче просят вывести две вещи: **количество** подошедших пар/троек и **максимальную** (или минимальную) сумму элементов среди них.

Вместо того чтобы заводить раздельные переменные счетчика количества пар `count = 0` и максимальной суммы среди всех пар `max_sum = -100000`, мы можем убить двух зайцев **одним списком для ответа**:

**Заключительная часть** решения [задания выше](#суть-задания):

```python
ans = []  # Список для ответа

for i in range(len(f) - 1):
    a = f[i]
    b = f[i + 1]
    if a % 33 == spec or b % 33 == spec:    # если пара подошла
        ans.append(a + b)   # сохраняем сумму элементов

# Выводим, сколько сумм элементов мы сохранили (т. е. сколько пар подошло)
# Выводим максимальную из сумм элементов
print(len(answers), max(answers))
```

1. **Количество найденных пар** мы получаем автоматически через длину списка: `len(answers)`.
2. **Максимальную сумму** мы находим одной встроенной функцией: `max(answers)`.
3. Мы застрахованы от глупой ошибки, когда для `max_sum` изначально задали слишком маленький ноль (`max_sum = 0`), а все суммы в файле оказались отрицательными, из-за чего программа выдала неверный ответ. Если нас попросят найти минимальную сумму, мы просто напишем `min(answers)`.

## Шаблон программы

Соберем все, что было оговорено выше, воедино:

```python
def c_(n):  # проверка значности
    return _ <= abs(n) <= _

def end_(n):    # проверка окончания
    return abs(n) % _ == _

def c_end_(n):  # одновременно значность и окончание (если позволяет условие задания)
    return _ <= abs(n) <= _ and/or abs(n) % _ == _

f = [int(x) for x in open("17.txt")]

spec = max([x for x in f if _(x)])  # прописать условие специального числа

ans = []
for i in range(len(f) - _): # -1 если двойка, -2 если тройка
    a, b = f[i], f[i + 1]
    c = f[i + 2]  # закомментировать если пара
    
    if _:   # прописать условие с использованием функций и spec
        ans.append(a + b + c) # убрать + c если пара

print(len(ans), _(ans)) # min или max
```
