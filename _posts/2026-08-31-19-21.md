## Теория игр

> **Теория игр** -- это раздел математики, который изучает ситуации, где **несколько участников принимают решения, влияющие друг на друга**.
{: .prompt-info}

В нашем случае всё очень просто:

- 👦 Петя делает ход;
- 👨 Ваня отвечает;
- 👦 Петя снова ходит;
- 👨 Ваня снова ходит;
- и так далее.
    

При этом каждый игрок хочет **выиграть**.

Поэтому недостаточно спросить:

> Могу ли я сделать хороший ход?

Нужно спросить:

> Могу ли я сделать такой ход, после которого я выиграю **независимо** от ответа соперника?

---

## Одна куча

Рассмотрим прототип задания на одну кучу.

### Суть задания

Представим игру:

> В куче лежит **S** камней.
>
> Два игрока - **Петя** и **Ваня** - по очереди делают ходы. Первым ход делает **Петя**.
>
> За один ход можно:
> - **добавить 1 камень**;   
> - **добавить 2 камня**;
> - **умножить количество камней на 2**.
>
> Игрок, который первым после своего хода достигает некоторого условия, например получает **не менее 30 камней** при $S<30$, выигрывает.

Вопросы во всех трех заданиях строятся примерно образом:

> При каком **минимальном значении S** Петя не может выиграть за один ход, но при любом ходе Пети Ваня выигрывает своим первым ходом?

Или 

> При каких **двух минимальных значениях S** выполняются оба условия:
> - Ваня может выигрвать за один или два хода
> - Ваня не может гарантированно выиграть за один ход

---

### Стратегия решения

Будем считать, что если при определенном значении $S$ Петя может победить за $N$ ходов, то эта позиция называется $ПN$. Тогда если Ваня может победить за $N$ ходов, то эта позиция называется $ВN$.

Тогда $П1$ -- это позиция, в которой Петя выигрывает **за один свой ход**. То есть из этой позиции Петя прямо сейчас может сделать ход и закончить игру.

Подберем позиции $П1$ для задания из [примера выше](#суть-задания):

Количество камней увеличивается больше всего при уможении $S$ на 2. Исходя из этого выразим $S_{min}$, при котором будет позиция $П1$:

$$
S\cdot 2 = 30\\
S=15
$$

Получим такую таблицу для $30< S\leq 15$:

|Значение $S$|$29$|$...$|$15$|
|-|-|-|-|
|**Позиция**|$П1$|$П1$|$П1$|

Для начального количества камней $S$ выведем гипотезу:

> Если **любой ходе** ведет в $ПN$, то **Ваня победит за $N$ ходов**
>
> Если **хотя бы один ход** ведет в позицию $ВN$, то **Петя победит за $N+1$ ходов**
{: .prompt-tip }

Докажем гипотезу на примере вычисления $П2$ и $В1$:

![Схема ходов для П2](/assets/img/19-21(1)-light.png){: .light }
![Схема ходов](/assets/img/19-21(1)-dark.png){: .dark }

Здесь мы понимаем: раз Петя, имея позицию $S = 15, 16, 28$ победил за первый ход, значит Ваня, попав в такую же позицию, тоже победит за один ход.

![Визуализация](/assets/img/19-21(2)-light.png){: .light }
![Визуализация](/assets/img/19-21(2)-dark.png){: .dark }

Здесь Петя в начале выбирает такой ход, что Ваня окажется в той позиции, в которой Петя проиграл (исходя из прошлого примера). Если Петя выберет другой ход (не $+1$), конечно, он проиграет. Однако, формулировки заданий 19-21 просят найти $S$, при котором игрок **может победить** при любом ходе противника. Может -- значит, есть хотя бы один такой ход. 

---

### Программное решение

Воплотим алгоритм аналитического решения:

1. Дано число $S$
2. Дано ограниченное количество ходов для игры
3. Если все ходы приведут в позицию $ПN$, то Ваня победит за $N$ ходов
4. Иначе Петя победит за $N+1$ ходов

Понятное дело, что число $S$, как и в аналитическом решении, мы будем перебирать. 

В аналитическом решении при определении победы игрока для значения $S$ мы определяли, будут ли ходы вести в победные позиции "предыдущих" значений S -- то есть, мы декомпозировали задачу, понятнее говоря разбили ее на мелкие подзадачи. В программе мы реализуем это с помощью [рекурсии](/recursion).

> Напишем функцию, которая будет возвращать $1$, если **нужный игрок победит**, и $0$, если проиграет.
{: .prompt-tip }

**Кто такой нужный игрок?** Это -- тот, кто должен победить по заданию.

Скажем, что $m$ - это сколько **всего** ходов должно быть сделано в игре по условию задания.

$m$|Кто победит 
-|-
1|П1
2|В1
3|П2
4|В2

Тогда результат работы рекурсии (победа игрока) будет зависить от следующих параметров:

- $S$ - количество камней в куче
- $m$ - сколько **всего** ходов в игре

Определим функцию с этими параметрами:

```python
def f(s, m):
```

Мы понимаем, что количество оставшихся ходов (из общего их количества) с каждым шагом рекурсии будет **уменьшаться**. Значит, если ходы закончатся, а необходимое количество камней не достигнуто, то это считается за **проигрыш** нужного игрока.

Давайте посмотрим, как определить, кто ходит, по четности $m$. Возьмем $m = 2$, при котором победит Ваня за $1$ ход:

|Сколько ходов осталось ($m$)|$2$|$1$|
|-|-|-|
|**Кто ходит**|Петя|Ваня|

Заметим, что игрок, который должен победить (Ваня) имеет **нечетные ходы**. 

Возьмем $m=3$, при котором победит Петя за $2$ хода:

|Сколько ходов осталось ($m$)|$3$|$2$|$1$|
|-|-|-|-|
|**Кто ходит**|Петя|Ваня|Петя|

И, опять же, игрок, который должен победить (Петя) имеет **нечетные ходы**.

> Игрок, который должен победить по условию, имеет **нечетные** значения $m$ в ходе игры.
{: .prompt-warning }

Значит, мы понимаем, что один из базисов -- это то, что в конце игры **до своего хода** в позиции $\geq 30$ должен оказаться игрок с **четным** $m$. Если это будет так, то мы говорим, что победил игрок с нечетным $m$. Легче всего это сделать с помощью возврата [логического выражения](/logic-expression), которое проверяет четность $m$.

Из-за того, что по сути у нас должно срабатывать это условие при $m=0$ (оно как раз будет четным), проверять, закончились у нас ходы или нет, мы будем **после проверки условия победы**:

```python
    if s >= 30: return m % 2 == 0   # условие победы
    if m == 0: return 0 # нет ходов
```

Теперь рекурсивно пропишем ходы -- для удобства сохраним результаты рекурсии в список. Не забываем уменьшать общее количество ходов при рекурсивном вызове:

```python
    h = [f(s + 1, m - 1), f(s + 2, m - 1), f(s * 2, m - 1)]
```

А дальше пропишем сам шаг рекурсии с использованием [тернарного оператора](). Как вы помните, для игрока, который должен победить, должен быть **хотя бы один выигрышный ($ВN$) ход**, а для его соперника **все ходы должны быть проигрышными ($ПN$)**. Для этого вспомним две команды:

> `all(список)` вернет `True`, если **все** значения в списке истинны, иначе `False`.
>
> `any(список)` вернет `True`, если есть **хотя бы одно** истинное значение, иначе `False`.
{: .prompt-info }

```python
    return any(h) if m % 2 != 0 else all(h)
```

Рекурсивная функция готова. Дальше дело за малым -- перебрать $S$ и найти такой $f(S)$, что функция будет возвращать $1$.

```python
for s in range(1, 30):
    if f(s, 3): # Петя победит за 2 хода
        print(s)
```

Или, используя [генераторы списков](/list-generator):
```python
print([s for s in range(1, 30) if f(s, 3)])
```

Условия также могут дополняться в зависимости от задания. Рассмотрим парочку из таких ситуаций.

> Найдите минимальное значение $S$, при котором выполняются оба условия:
> - Петя не может победить за $1$ ход
> - Петя гарантированно победит за $2$ хода

То, что Петя **не может победить** за $1$ ход, мы пропишем в виде `not f(s, 1)`, ведь `f(s, 1)` буквально означает, что Петя **может победить** за 1 ход.
```python
print(min([s for s in range(1, 30) if not f(s, 1) and f(s, 3)]))
```

### Неудачный ход

В задании №19 иногда встречается условие про неудачный ход Пети. При таком условии если у Пети при первом его ходе есть **хотя бы один ход** (вместо **всех ходов** в стандартном условии про гарант победы) в $ПN$, он в него сходит и таким образом приведет Ваню к победе.

Рассмотрим условие:

> Найдите минимальное значение $S$, при котором Ваня побеждает своим первым ходом после **неудачного хода Пети**.

Это означает, что в шаге рекурсии `any(h)` теперь будет работать для всех игроков. Часть тернарного оператора мы можем закомментировать.

```python
    return any(h) # if m % 2 != 0 else all(h)
```

> Не забудьте для №20-21 убрать комментирование, вернув функцию к стандартному виду!
{: .prompt-danger }

Общий вид программы:

```python
def f(s, m):
    if s _: return m % 2 == 0 # прописать условие победы
    if m == 0: return 0
    h = [f(s _, m - 1), f(s _, m - 1), f(s _, m - 1)] # прописать ходы
    return any(h) if m % 2 != 0 else all(h) # закомментировать тернарку при условии неудачного хода

# можно прописать min(), max() для генераторов в зависимости от условия
print("19)", [s for s in range(_, _) if f(s, _)])
print("20)", [s for s in range(_, _) if f(s, _) and not f(s, _)])
print("21)", [s for s in range(_, _) if f(s, _) and not f(s, _)])
```

## Две кучи

> Теперь куч **две**. В одной куче лежит фиксированное количество камней $N$, которое дают в задании, остается найти параметр $S$ для второй кучи.
>
> И вот тут появляется главный вопрос:
>
> **Какую кучу изменять своим ходом?**
>
> Но пугаться не нужно. Принцип решения остаётся абсолютно тем же.
{: .prompt-info }

---

### Суть задания

Обычно в условии говорится примерно следующее:

> На столе лежат две кучи камней. **В первой куче $7$ камней**, во второй -- $S \leq 15$ камней.
>
> За один ход игрок может:
>
> * **добавить $1$ камень в одну из куч**;
> * **увеличить количество камней в одной из куч в $2$ раза**;
>
> Побеждает тот, кто после своего хода первым получит суммарно **не менее $30$ камней** в двух кучах.

### Стратегия решения

Теперь обозначение позиций меняется. Раньше мы обозначали одно число за позицию, а теперь указываем значения из **двух куч**:

$(S1, S2) - П1$

Рассмотрим схему:

![Схема ходов](/assets/img/19-21(3)-light.png){: .light }
![Схема ходов](/assets/img/19-21(3)-dark.png){: .dark }

Схема заметно усложнилась. Неудивительно, что с 2025 года прототип на две кучи практически всегда выпадает на реальном ЕГЭ -- такова тенденция усложнения заданий.

Но и здесь при рассчете $П2$ мы видим такую же картину, как и при решении задания с одной кучей: если Петя может сходить в позицию $В1$ **хотя бы одним** способом, то мы получим $П2$ в начальной его позиции.

> В задании на две кучи усложняется рассчет основополагающих позиций $П1$, необходимых для рассчета $В1$, $П2$ и т. д.
>
> Однако система нахождения $В1$, $П2$ и пр. остается такой же: если из позиции есть **хотя бы один** способ попасть в $В1$, то победит **Петя**. **Иначе** победит **Ваня**.
{: .prompt-warning }

### Программное решение

Никаких значительных изменений относительно [программного решения на одну кучу](#программное-решение): 
* Добавить новый параметр $S_2$;
* Изменить базис победы;
* Прописать больше ходов. 

Полный шаблон программы выглядит следующим образом:
```python
def f(s1, s2, m):
    if s1 + s2 _ : return m % 2 == 0 # вписать условие победы
    if m == 0: return 0
    h = [f(s1 _, s2, m - 1), f(s1 _, s2, m - 1), f(s1, s2 _, m - 1), f(s1, s2 _, m - 1)] # вписать все ходы (ЗА 1 ХОД МЕНЯЕМ ОДНУ КУЧУ!)
    return any(h) if m % 2 != 0 else all(h) # закомментировать тернарку при неудачном ходе

# вписать диапазон S, сколько камней в первой куче и общее число ходов из условия
print("19)", [s for s in range(_, _) if f(_, s, _)])
print("20)", [s for s in range(_, _) if f(_, s, _) and not f(_, s, _)])
print("21)", [s for s in range(_, _) if f(_, s, _) and not f(_, s, _)])
```
